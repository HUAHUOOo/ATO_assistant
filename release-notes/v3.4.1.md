## 更新

3.4.1 以修复为主，修掉了几处会实际损坏数据、或者让功能直接不可用的问题：旧 Android（7～12L）上局域网 API 会调用系统里不存在的方法，请求失败还可能把应用结束掉；地图打标保存一次就会把 400 多处阵营数据从标签文件里删掉，两个页面同时保存还会互相覆盖；整份战役存档导入只要有一个模块失败，就会在服务器上留下新旧混合的存档；战役简报快速切换循环时，慢的旧请求会把页面切回去；AIBP 两个页面的牌堆会互相覆盖，第二屏同步失败则完全没有反馈。装备制造现在会显示本循环与后续所有循环里已解锁的生产科技（提前拿到后面循环的科技卡也能造）。记录表的宿敌「切换」按钮独占一行右端、候选向左展开，不再被标题列压住或被面板裁掉。战役简报新增「故事与灾祸卡面」与「内蕴奥德赛 / 冒险中枢进度」两块回放。

## 修复

### 旧 Android 的局域网入口不再调用新系统方法

- `tools/packaging/android/.../LocalSecondScreenServer.java` 的手写查询串解析原先用 `URLDecoder.decode(String, Charset)`：这个重载 Android 13（API 33）才加入，而应用声明的最低系统是 `minSdk = 24`。旧手机上**任何带查询参数的局域网 API 请求**都会抛 `NoSuchMethodError` —— 主控台自己就用 `?section=dashboard`，所以局域网入口一用就中。这段代码跑在线程池里，而 `handle()` 只 `catch (IOException)`，未捕获的 `Error` 会直接结束整个应用进程。
- 现在固定走 API 1 起就存在的 `decode(String, "UTF-8")` 重载，异常在这一处收敛成调用方已经处理的类型。
- 补了验证层：`tools/test_android_query_parameter.py` 除了原有的转发边界校验，还钉住 `minSdk = 24`，并禁止 `URLDecoder` / `URLEncoder` 的 `(String, Charset)` 重载再被写回来。

### 地图打标：保存不再删字段，也不再互相覆盖

- **保存一次就丢数据**：`api/map-tile-tags.php` 与 `tools/tag-editor.js` 的归一化原来从零拼一个新对象，把编辑器不认识的键全部丢掉 —— `map/map-tile-tags.js` 里有 424 处 `factions` / `factionUpdatedAt`（地图阵营显示用）和标签定义的 `cycles`，而且仓库里没有第二个地方能再生成它们。现在两端都改成「从原对象出发、只覆盖已知字段」，`version` 也只增不减（老客户端回传 1 不会把文件从 2 降级）。
- **互相覆盖**：标签接口新增递增 `revision`，写入时在专用锁文件里「读取—比较—替换」，版本对不上就回 `409 SAVE_CONFLICT` 且一个字节都不写；编辑器带上 `expectedRevision`，冲突时保留本页改动，并给出「载入服务器版本 / 用本页覆盖」两个选择，冲突未解决前不再自动重试（旧实现只对临时文件加锁，能防写坏文件，但挡不住这种丢失更新）。
- 打标页面与脚本的缓存号已提升。**如果你还开着旧缓存的打标页面，它保存时仍会丢字段 —— 刷新一次页面即可。**

### 整份存档导入改为「全成功或全不写」

- 以前导入是逐个模块 POST（七个请求）：任何一个失败（版本冲突 / 网络中断 / 500），已经写进去的模块就留在服务器上，界面只报一句「导入失败」，于是地图、英雄、资源可能分属两份不同的存档，而本页内存也已经被替换成导入内容。
- 现在后端新增 `action=import-sections`：在战役写锁内先校验**全部**模块的 `expectedRevision`，任何一个对不上就整份拒绝并回报是哪些模块（409 + `sections` 明细），全部通过才备份并一次性落盘。
- 前端改成一次请求；失败时**不再切换本页存档、不推进保存基线与版本号**，并把冲突模块逐个列出来。导入前还会先等一次防抖保存落盘，避免导入前的内存状态在导入之后又被写回 `dashboard`。

### 战役简报：最后一次选择才生效

- `briefing/briefing-app.js` 的 `load()` 现在每次请求领一个递增 token，响应回来时若自己已经不是最新请求就整个丢弃（连它自己的错误提示也不弹），并用 `AbortController` 取消被取代的请求。以前快速切换循环时，较慢的旧请求后到会把页面（包括循环下拉框）切回旧循环。

### AIBP：第二屏同步有反馈，多标签页不再互相覆盖

- 第二屏快照发送原来只有「版本冲突」会重试，其它错误（网络 / 5xx / 响应没有 JSON）直接静默返回：本页牌堆继续变化，第二屏停在旧内容，开关却仍显示已开启。现在第二屏开关旁有「同步中 / 已同步（时间）/ 同步失败（原因）」，临时故障最多重试 3 次（1s → 3s 退避，同一时刻只有一个在途请求），登录失效只提示刷新页面、不重试。
- 两个 AIBP 页面同时打开时，`savePiles()` 会先把自己读到的原文与当前 `localStorage` 比对（并用 `storage` 事件记录对方的写入），发现别人改过就不再静默覆盖，而是让用户选「载入对方的最新牌堆」或「用本页覆盖对方改动」。单页面路径行为不变，也不会弹框。

### 装备制造：显示本循环和后续所有循环的已解锁生产科技

- 「只显示本循环装备」这个筛选默认开着，而判定只放行本循环与「更早循环里持续存在的宿敌生产科技」。于是提前解锁的后续循环科技虽然已经在已解锁列表里，却被这一步滤掉，界面上既看不到、也造不出来。
- 现在判定放宽为「本循环 + 所有后续循环」，勾选框文案改成「**只显示本循环及以后装备**」；不属于本循环的装备在名称后加「循环 N」角标，说明它为什么在这里。
- 制造费用照旧按生产科技自己所属循环的资源记账（`craftPlanForGear()` 用的是 `entry.cycle`），材料足够就能照常制造入库；更早循环仍然只保留那 9 项「持续存在的宿敌」生产科技。

### 文档与测试整理

- `README.md` 与 `briefing/api.php` 里「装备库存与资源收支只存在于浏览器本地」的说法已改正：它们保存在存档的 `record` 模块（科技页读写），简报只是还没有为它们做差分展示。
- `tools/test-aibp-token-loading.cjs` 拆成「名单格式」（公开 clone 必过）与「本地素材体检」（只在本地确实有 token 图片时跑；名单里的图缺失才算失败，本地多出来的图只打印一条提示并说明怎么加进名单）。此前它把「本机素材目录与内置名单不完全一致」当成功能缺陷。
- 修掉上一笔合并带出来的测试桩缺陷：`tests/dashboard-constant-sync.test.cjs` 的抽函数清单漏了 `normalizeState` 依赖的 `normalizeNemesisSelections` / `migrateNemesisProgress` / `normalizeNemesisResourceHistory` / `evolutionStages` / `getEvolutionStage`，整组用例一开跑就 `ReferenceError`。
- `tools/test_android_signing.py` 现在显式带 `-ExecutionPolicy Bypass` 运行生成的脚本（工作流里那一步是 `shell: pwsh`），并在本机只有 Windows PowerShell 5.1 时明确跳过，而不是假失败或假通过。

## 记录表：宿敌「切换」按钮

- 「切换」从宿敌标题格里搬出来，独占宿敌行最右一列（该行加 `nemesis-row`，CSS 改成三列 `minmax(124px,max-content) minmax(0,1fr) auto`）。以前标题列最窄会压到 124px，按钮被右边的等级格盖住。
- 候选从原生 `<select>` 换成自绘按钮列表：`role="menu"` + `menuitemradio` + `aria-checked`、当前宿敌高亮，列表贴按钮左缘向左展开（`right: calc(100% + 6px)`、垂直居中、`z-index: 20`、可换行），不再被 `.panel { overflow: hidden }` 裁掉。
- 开合：再点收起；展开期间才挂 `document pointerdown` 捕获监听，点菜单外收起并立即摘掉；Esc 在按钮上和菜单里都能收起。单选宿敌的循环（c1 / c4 / c5）按钮置灰，提示「当前循环的宿敌固定」。
- 选中候选后的三步（`selectNemesis()` → 重渲染敌人轨与资源 → `queueSave()`）与旧的 `change` 处理器完全一致，**存档结构与迁移都没有变化**（本次没有触碰 `normalizeState` / `migrateEnemyStages` / `migrateNemesisProgress`），老存档照旧可读；主控台与地图的宿敌战斗跳转读的是同一份 `nemesisSelections`，写入路径未变，行为不变。
- 窄屏（≤640px）宿敌行回到一列；`record.css` 缓存号提到 `?v=20261003-nemesis-right`。

## 下载与升级

本版本提供 Android APK、Windows x64、macOS Apple Silicon / Intel 便携版，以及 Docker 镜像 `3.4.1`；Docker 的 `latest` 标签同步更新。

- Android：下载 `ATO-Assistant-3.4.1.apk`，覆盖安装。**旧 Android（7～12L）的局域网入口修复需要这一版 APK。**
- Windows：下载 `ATO-Assistant-Portable-3.4.1-windows-x64.zip`，或使用便携版内置更新。
- macOS：按芯片选择 `ATO-Assistant-Portable-3.4.1-macos-arm64.zip` 或 `ATO-Assistant-Portable-3.4.1-macos-x64.zip`。
- Docker：拉取镜像并重建服务；固定版本用户将 `ATO_VERSION` 改为 `3.4.1`。
- 资源包：沿用 3.4.0 的两份 `.atopack`，本次不需要重新导入。

手动替换程序时保留原来的 `data/` 与本地素材目录。公开程序包不包含游戏图片、完整故事、音乐、资源包或用户存档。
