## 更新

3.5.0 让主控台的「导入状态」可以直接吃官方 App 的存档：选一份 `.jsave`，按**内容**认出来之后转成 ATO 的存档分区，和平时导入状态包走同一条路。**地图是完整导进来的** —— 已探索的格子、已揭示的格子、格子笔记跟着一起落位（实测一份第 5 循环的存档：63 格已探索、3 格已揭示、1 条格笔记），不会再出现"导完打开地图，格子全是未探索"的情况。官方存档里 ATO 没有落点的内容（战役 UID、战斗记录、忆识剧场、密语、配装、时间回环、属性上限……）不再被默默丢掉，而是以带前后标识的文字区块写进记录表笔记，重跑不会叠两份。因为笔记是整串替换，导入前会先提示会不会覆盖掉已有的记录表笔记，点取消就整段中止、服务器零改动。记录表的泰坦列表新增「已死亡」字段，每行的「删除」键改成「死亡」键，按一下就把该行数量累加进已死亡数。

## 新增

### 主控台「导入状态」可以直接导入官方 App 的 `.jsave` 存档

- 新增 `assets/jsave-import.js`（`jsave-import/import_jsave.py` 的逐字段 JS 移植：对外是 `isJsave` / `parseJsave` / `convert`，浏览器挂 `window.ATO_JSAVE_IMPORT`，node 走 `module.exports`）与 `assets/jsave-tables.js`（官方枚举与卡名数据表：86 项货舱、41 个 hub、15 个阵营、319 张科技卡英文名、497 个装备卡号，值以 JSON 文本分段存、加载时 `JSON.parse` 一次）。
- `index.html` 按 **`jsave-tables.js` → `jsave-import.js`** 的顺序在 `map/map-data.js` 之后引入（表必须在转换器之前；转换器用 `window.ATO_MAP_DATA` 落地图瓦片），两个文件都带 `?v=20261004-jsave-map`。「导入状态」按钮补了 `title`，`<input accept>` 放行 `.jsave`，但**扩展名不参与判定**。
- **按内容判定**：官方存档的前 3 字节是不透明头（实测 `81 ae 05`），`isJsave(bytes)` 直接看内容，所以改过名的存档照样认，改过名的 ATO 状态包也不会被误判。
- **容忍官方存档的陈旧尾巴**：官方 App 覆盖写入时不截断，JSON 后面可能残留旧数据（实测最多 31KB）。`parseJsave` 用括号/字符串感知的扫描器取「前 3 字节头 + 第一个完整 JSON 值」，并把 `staleTail` 一起回报，而不是把整个文件丢给 `JSON.parse`。
- 转换出来的结果走的是与常规导入**完全相同**的 `applyImportedSections()`，`sectionRevisions` 语义、防抖保存先落盘、失败时本页不切换存档这些行为一字未改。`.jsave` 只转换得出 `dashboard` / `record` / `map` / `technology` / `heroes` 五个分区，`isFullBackup` 传 `false`，**没转换出来的分区不会被清空**；`campaign_cycle` 超出 `c1..c5` 时明确报错而不是导进错循环。
- 常规 ATO 状态包那条路径没有改动：`FileReader` 从 `readAsText` 换成 `readAsArrayBuffer` 只是为了拿到字节，JSON 分支的行为与此前一致，`tests/jsave-import.test.cjs` 里有专门一条用例钉住它。
- 与验证过的 Python 转换器**除地图分区外逐叶子 0 差异**：对象按键集合并、数组按下标、标量 `JSON.stringify` 相等，唯一豁免是 Python `unique_id()` 的毫秒时间戳 id 行；另有 canonical 形式逐行比对。参考实现是冻结快照（`tests/fixtures/jsave/pysnap/`），不会因为 Python 侧后续再改而变成移动靶。地图分区之所以例外，见下面「地图完整导入」一节 —— 那是本轮唯一一处 JS 版**故意**比 Python 版多做的事，测试里额外钉住"Python 已有的部分（`tokens` / `tileVariants`）一个字都没改"。

### 地图完整导入：已探索 / 已揭示 / 格子笔记 / 格上指示物

- 官方存档的 `maps[]` 是**同一张地图面上的分片**（实测 c1 是 32 + 80、c3 是 80+80+80+9，用户把它们平铺成一张）。转换器逐个分片建立**下标 → ATO tileId** 的对应关系，挑第一个能确定的；对不上的分片跳过并在诊断里留话，绝不硬塞。三种算法，按可信度排序：
  1. **锚点解算（首选）**：官方存档自己带着交叉引用 —— `campaign_stats.argo_tile` / `adversary_tile` / `city_tile` 是那三个标记所在板块的**编号**，per-tile 的 `argo` / `advr` / `toks[0]` 是它们在**数组里的下标**；两个以上锚点就能解出 `(列数, 行偏移, 列偏移)`，再逐格换 id（只有**唯一占用**的格才换，有歧义的格跳过并记进诊断）。
  2. **外接矩形网格**：没有锚点时，分片格数等于该轮数字板块的外接矩形面积就按格换 id。
  3. **按下标对位**：分片格数与板块列表长度相同（最早的行为，只在没有网格信息时用）。
  - 五轮实测**三锚点全中、解唯一**，且与用户截图的 O 编号一致：c1 第 2 张分片（10 列，起点格 0,3）40/41/60 → `021`/`022`/`031`；c2（8 列，96=12×8）72/89/88 → `064`/`079`/`078`；c3 第 1 张（10 列，起点格 1,0）42/43/52 → `002`/`005`/`001`；c4（9 列，9×9）56/55/45 → `021`/`020`/`028`；c5（10 列，8×10）56/69/20 → `057`/`070`/`021`。
  - **c4 说明为什么不能靠"格数相同就按下标对位"**：ATO 的 c4 表是 81 格、无空洞，但 id 与网格顺序不一致（id `021` 在行优先第 56 格），按下标对位会得到 `058` ✗ —— 所以这条老规则已经降为最后手段。
  - **c3 的已知缺口**：ATO 的 c3 板块表有 70 处坐标重复（92 个板块只落在 22 个格上），除锚点外大部分格无法可靠换 id —— 实测只落位 5 格（`001/002/005/009/014`），其余进诊断。要彻底修需要修 ATO 的 c3 板块坐标或拿到官方 c3 分片几何。
- 上一版只导了棋子位置、变体面和"最后到访城市"，`expl`（已探索）、`revl`（已揭示）、`note`（格笔记）、`toks`（格上指示物）全都没导 —— 用户导入第 5 循环的存档后打开地图，本来已经开出来的 63 格全部显示成未探索，格子上的指示物图标也一个不剩。现在：
  - `expl` → `map...cycles.<循环>.explored["<格 id>"] = true`（c5 实测 **63 格**，测试里逐个 id 与官方 `expl` 对照，`expl=false` 的 17 格逐个断言**没有**被写成已探索）；
  - `note` → `tileNotes["<格 id>"]`（字符串；c5 实测 1 格，`026` = `通用指示物` —— 那是用户随手写的笔记，与指示物位序无关）；
  - `revl` → `previewRevealed["<格 id>"]`，**只写未探索的那些**（c5 实测 3 格：`008` / `065` / `070`；c1 实测 2 格：`026` / `027`）；
  - `toks` → `tokens.markers["<格 id>"]["<指示物 id>"] = true`（映射见下）。
- `revl` 的语义结论（规则也写在代码注释里）：官方 `revl` 是**每格一个布尔**（本档 7 格），不是"某一个最新揭示"——ATO 的单值键 `latestRevealedTile`（"最近一次新翻开的板块"）装不下 7 个标志位，也不含顺序信息，所以**不写它、不编造顺序**；能装下集合的只有 `previewRevealed`（"已揭示但还没探索"，渲染时与已探索一样显示正面）。同时 `expl=true` 的那 4 格不写：它们已经由 `explored` 覆盖，ATO 自己在探索时也会删掉这个键。这条规则在"曾经揭示过"和"当前已揭示未探索"两种读法下结果一致，实测旁证是真实 ATO 存档里仇敌停在未探索板块上时，那张板块正是在 `previewRevealed` 里。
- **`toks` 位序的依据**（三条互相独立，缺一不写）：
  1. **官方 App「Edit Tile」面板的逐行顺序**（用户提供 c1–c5 各一张截图）。c5 面板第三组去掉 `UNDERWATER TILE`（格子属性，ATO 没有对应指示物）后恰好 8 行 = c5 的 `toks` 位数；c4 面板 7 行 = 实测 c4 `toks` 7 位；c3 面板 5 行 = 实测 c3 `toks` 5 位 —— 三处**行数与实测位数完全吻合**。
  2. **字段槽位结构**：存档里 `expl/revl` 之后依次是 `argo`、`advr`、`add_advr[2]`、`toks[N]`、`note`，而面板的 ARGO / ADVERSARY 组后面恰好还有 NEMESIS / BLACK BEAK 两行 —— `add_advr` **在 c5 恰好 2 位、其余循环是空数组**，两者对齐。
  3. **ATO 注册表同名 id**：`map/app.js:301` 的标记池（标签见 `asset-studio/app/catalog.py` 的 `MAP_TOKEN_LABELS`）里逐行都有同名 id（`c5_last_visited_underwater_city` / `last_silver_ruin` / `c5_ruin` / `c5_atlantean_capital` / `hs` / `ENGIN` / `night_nymph` / `token_2` / `c4_city_of_squalor` / `c4_cloud_ship` / `last_oasis` …）。
  - **硬交叉验证（两处）**：`campaign_stats.city_tile` 与"全图唯一一个 `toks[0]` 为 true 的格子"在 c5（21 ↔ 021）与 c2（78 ↔ 078）上**都是同一格** → 面板第 0 行 `LAST VISITED CITY` 就是 `toks[0]`；c2 位 1 / 位 2 落到的那两格，截图里正好各有一个 HEMIOLIA SCOUT（蓝底船）与 ENGINE NYMPH（暗色），与面板顺序一致。
- 已落位的位序：**c2** `toks[1]`=`hs`、`toks[2]`=`ENGIN`；**c3** `toks[1..4]`=`token_2`（ARIADNE'S ANCHOR）/`hs`/`ENGIN`/`night_nymph`；**c4** `toks[1..6]`=`c4_city_of_squalor`/`c4_cloud_ship`/`last_oasis`/`hs`/`ENGIN`/`night_nymph`；**c5** `toks[1..7]`=`c5_last_visited_underwater_city`/`last_silver_ruin`/`c5_ruin`/`c5_atlantean_capital`/`hs`/`ENGIN`/`night_nymph`（c5 实测 6 格：`021` → `c5_ruin` 且与 `last_city` 同格合并、`026` → `c5_last_visited_underwater_city`、`033`/`051`/`066` → `c5_ruin`、`065` → `hs`）。
- **位 0（`LAST VISITED CITY`）不单独写标记**：ATO 的「最后到访的城市」已经由 `campaign_stats.city_tile` 落成 `markers.<格>.last_city`（官方自己也把这一格镜像成全局 `city_tile`），再写一次是重复；若哪天位 0 落在不是 `city_tile` 的格子上，转换器诊断里会留下 `toks_bit0_conflict` 供排查。
- **还没有依据的就不猜**：**c1** 的 `toks` 一位都不写 —— 面板那三行（`LABYRINTHIAN TEMPLE` / `CITY OF THE BULL` / `SEPULCHER ACROPOLIS`）对应的 ATO id 是不透明的 `c11`/`c12`/`c13`，名字对不上，而且用户截图里"ENGINE NYMPH 在 O28/O33 附近"与"面板顺序即位序"（照顺序会落在 O23）对不上，还缺一次确认。
- 仍不导入：`reward_token`（官方枚举 `RewardTokenType` = Hull / Crew / Titan / ArgoKnowledge / DreamofPharos / RRToken，第 0 项 `Hull` 是默认值 —— 全部样例**每格**都是它，代表"该格的奖励类型"而不是"放了东西"；只有 `has_reward_token` 为 true 才有落位可言，而样例里全是 false）与 `add_advr`（面板那两行是 NEMESIS / BLACK BEAK，ATO 里也有同名标记 `c5_nemesis` / `c5_black_beak`，但"额外仇敌位 ↔ 指示物"这一步还缺一次用户侧确认，先不写）。上面这些"没导"的项全部记进 `convertWithReport().stats.map_detail.unmapped`。
- **一格都不许错位**：只有在「能读到该轮板块表 + 至少一个分片能确定对应关系」时才落位，否则**整个地图一个字段都不写**，并在诊断里给人话（`地图分片格数 …都对不上，未落位` / `读不到 map/map-data.js 里 cN 的格表…未落位`）。上一版在"读不到格表"时会退化成裸序号（`"57"` 而不是 `"057"`），对已探索/笔记这类按格 id 存的数据等于整套键都错，所以这版收紧了守卫。诊断里还会列出没落位的分片（`skipped_maps`）与官方数组里 ATO 没有对应板块的格子（`missing_official_cells`）。
- 「最后到访城市」（`campaign_stats.city_tile` → `tokens.markers["<格 id>"].last_city`）与棋子位置 / 变体面的落位规则**一字未改**（城市标记改成**合并**写入，好与同一格上的 `toks` 指示物共存）。

### 官方存档里「导不进 ATO」的内容写进记录表笔记

- 官方顶层键里 ATO 完全没有落点的部分不再丢弃，而是以带首尾标识的区块追加到 `record.notes`：
  - 开头 `──────── 官方存档未导入项（由 .jsave 导入生成，勿手改） ────────`，结尾 `──────── 官方存档未导入项 结束 ────────`。
- 区块内容包括：战役 UID / 战役开始时间 / 战役名、战斗记录、忆识剧场 boss 轨道与泪珠·登升核心（含笔记）、密语语言、配装（`loadout_list`）、时间回环、传送门目标、属性上限无落点、属性值无落点、轮次步骤、皮格马利翁、下战斗笔记、资源无对应行、地图格笔记。
- **整块字符上限 4000**（`NOTES_BLOCK_LIMIT`），超限时先砍最长的那条明细、再整行省略，并留下 `（明细已截断，完整内容见导入报告）`；单行值上限 160 字符，列表超过 12 项时留前 8 项并标出总数。
- **幂等**：`stripNotesBlock()` 靠前后标识认出旧区块，重跑（或把生成结果二次导入）先剥掉旧的再追加，不会叠成两份。
- **用户自己的笔记始终在区块之前**：`campaign_notes` 逐条 + `matrix_notes` 解析后的残留行排在上面，生成的区块只追加在后面。
- 本档实测产出 32 行 / 1070 字符，与 Python 版**逐字符相同**（本轮地图侧新增的"未导入"信息**刻意不进这个区块**，否则 `record` 分区就会与冻结的 Python 参考快照产生差异；它只出现在转换器诊断里，见「已知限制」）。

### 导入前提示：记录表笔记会被覆盖

- 导入状态是整份替换 `record` 分区，所以目标战役里手写的记录表笔记会被这次导入带进来的内容整段取代，而且没有自动恢复的入口。现在写服务端之前先摊平比一次，**两边都有笔记且内容不同**才弹 `confirm`：空档没什么可丢的、重复导入同一份存档也不该打扰用户。
- 判定会同时收 `<用户桶>.notes` 与 `<用户桶>.cycleStats.<循环>.notes`：记录表页面改笔记时写的是 `cycleStats.<循环>.notes` 并把顶层那份删掉，只看顶层等于对真实存档永远不报警。桶 key 不一定是 `default`（官方存档写 `default`，页面按账号 id 分桶），旧存档把 `notes` 直接放在 `record` 顶层的形状也认。
- **点「取消」= 整段中止、服务器零改动**：比较发生在 `flushCampaignSave()` 之前，取消时连待写入的防抖保存都不会发生，只弹一句「已取消导入：没有写入任何分区」。

### 记录表新增「已死亡泰坦」

- 新增 `record.deadTitans`（**字符串**、顶层、不按循环）；官方存档的 `dead_titans` 也落到这里。
- 「泰坦」面板新增「已死亡」输入框（`#deadTitansInput`），`normalizeDeadTitans()` 把值归一到非负整数字符串；列表计数行变成 `总数 x/y · 残废 n · 已死亡 m`。
- 泰坦列表每行的「删除」键改为**「死亡」**键（`titan-remove titan-death`）：按一下把该行从列表移除，并把这一行的「数量」累加到已死亡数，`aria-label` 里写明本次 `+N`，按钮 `title` 说明这个行为。

## 已知限制

- 官方「Fated Events」进度与各定数框状态**不在 `.jsave` 里**（存在设备本地），因此无法导入。实测官方存档的 58 个顶层键里没有任何 `fated` / `const` / `hub` / `event` 键。
